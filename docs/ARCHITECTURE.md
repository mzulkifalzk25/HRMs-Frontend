# FormbaxHR — Frontend Architecture

> Where code goes, what may import what, and naming. Based on D-024 (structure) and D-026 (service layer).
> Rules marked **[lint]** are enforced by `pnpm lint` (`.oxlintrc.json`); the others are review rules.
> Created in P1-T08 (2026-11-25). Update this file when a structural decision changes, and record the decision in `docs/DECISIONS.md`.

---

## 1. Folder map

Folders are created by the task that first puts a real file in them (Git does not track empty folders, and the plan forbids placeholder files).

```text
src/
├── main.tsx                 Entry point: validates env, mounts error boundary + providers + router
├── index.css                Tailwind entry + design tokens (single source; see D-036)
├── app/                     Composition root: wiring only, no business logic
│   ├── router/              Route table, lazy route modules
│   ├── providers/           QueryClient, toasts, error boundary, auth provider
│   ├── layouts/             App shell (shell/ holds its parts), auth layout later
│   ├── guards/              Route guards (UX only; backend is authoritative, D-027), Phase 2
│   └── navigation.ts        Sidebar navigation config
├── components/              Shared, feature-agnostic UI
│   ├── ui/                  shadcn/ui primitives, generated by `pnpm shadcn add` (do not hand-edit)
│   ├── shared/              Composed building blocks (page header, status badge, ...)
│   ├── tables/              Data-table wrappers (TanStack Table v9)
│   ├── forms/               FormField (label/hint/error wiring), PasswordInput
│   ├── charts/              Chart wrappers (Recharts)
│   └── feedback/            Skeleton, empty, error, confirm dialog
├── features/<feature>/      One folder per domain (authentication, dashboard, employees, attendance,
│   │                        leaves, approvals, organization, imports, reports, notifications, audit, settings)
│   ├── api/                 <x>.service.ts (interface), <x>.http.ts, <x>.mock.ts, use-<x>.ts (TanStack Query hooks)
│   ├── components/          Feature-specific presentation components
│   ├── pages/               Route-level screens
│   ├── schemas/             Zod schemas (forms, API boundaries)
│   ├── lib/                 Pure business logic (policy, calculations), unit-tested
│   ├── types.ts             Feature types
│   └── index.ts             Public API of the feature (what other folders may import)
├── services/
│   ├── api/                 Central typed HTTP client, ApiError, request helpers
│   ├── auth/                In-memory access token, cross-tab refresh lock (Web Locks), auth channel (BroadcastChannel)
│   ├── mock/                Shared mock infrastructure: latency, mock viewer (`mock-session.ts`), in-memory HR backend with fictional seed data (`hr-store.ts`), attendance backend built on its scope (`attendance-store.ts`)
│   ├── health/              System health service (reference implementation of the service pattern)
│   └── registry.ts          Picks HTTP or mock implementation per domain from VITE_USE_MOCK_API
├── hooks/                   Shared React hooks (not feature-specific)
├── lib/                     Shared pure utilities (cn, date/time helpers, env)
├── types/                   Shared types: `hr.ts` (leave types, statuses, allowances), env types
├── constants/               App-wide constants (APP_TIMEZONE, route paths)
├── styles/                  Extra global CSS only if index.css grows too large (unused so far)
└── test/                    Test setup and test-only helpers (not shipped)
```

## 2. Dependency rules (who may import whom)

| From ↓ may import → | `app/` | `features/` | `components/` | `services/` | `hooks/` `lib/` `types/` `constants/` |
|---|---|---|---|---|---|
| `app/` | ✓ | ✓ (via `index.ts`) | ✓ | ✓ | ✓ |
| `features/<x>/` | — | own folder; other features only via their `index.ts` | ✓ | `services/api/`, `services/registry.ts`, service contract types (`*.service.ts`) | ✓ |
| `components/` | — | **✗ [lint]** | ✓ | — | ✓ |
| `services/` | — | feature `api/` contracts and implementations (registry only) | — | ✓ | ✓ |
| `hooks/` `lib/` `types/` `constants/` | — | — | — | — | ✓ (no React components in `lib/`) |

Additional rules:

0. **Registry-reachable modules import pure modules, not feature indexes [lint: no-cycle].** Schemas, service contracts, `*.http.ts`, `*.mock.ts`, `services/mock/**` and pure `lib/` code import other features' `types.ts`, `schemas/` or `lib/` directly. A feature's `index.ts` re-exports pages, pages import the registry, so importing an index from there creates a cycle.
1. **No mock imports outside the service layer [lint].** Only `src/services/**`, `*.mock.ts` files and tests may import `*.mock` modules or `src/services/mock/**`. Screens, components and hooks get data through TanStack Query hooks → service interface → registry (D-026).
2. **No import cycles [lint]** (`import/no-cycle`).
3. **Business rules live in `features/<x>/lib/`** as pure functions with unit tests: attendance classification, durations, leave balances, routing, workflow, hierarchy checks. Components only display results.
4. **Time:** every policy decision goes through the shared date/time helpers using `APP_TIMEZONE = 'Asia/Karachi'` (D-038, P1-T12). Never use the browser timezone or `new Date().getHours()` for policy.
5. **Frontend permission checks are UX only** (D-027). Never rely on them for security.
6. **No payroll or salary fields** anywhere (D-053).

## 3. Service layer pattern (D-026, P1-T11)

```text
Screen → use-leaves.ts (TanStack Query) → LeaveService (interface)
                                             ├── leave.http.ts  → services/api client → Django
                                             └── leave.mock.ts  → services/mock store (fictional data)
services/registry.ts chooses http or mock from VITE_USE_MOCK_API
```

- Interface and both implementations share the same types and Zod schemas.
- Switching `VITE_USE_MOCK_API` must not require any change in screens.
- Mock mode is always visible in the UI (P1-T16). Mock data is fictional and clearly labelled.

## 4. Naming conventions

| Kind | Convention | Example |
|---|---|---|
| Files and folders | kebab-case | `leave-balance-card.tsx`, `use-leave-requests.ts` |
| React components | PascalCase export | `export function LeaveBalanceCard()` |
| Hooks | `use-` file, `use` export | `use-leave-requests.ts` → `useLeaveRequests` |
| Service contract / implementations | `<x>.service.ts`, `<x>.http.ts`, `<x>.mock.ts` | `leave.service.ts` |
| Zod schemas | `<x>.schema.ts`, export `<name>Schema` | `leaveRequestSchema` |
| Tests | next to the source, `*.test.ts(x)` | `policy.test.ts` |
| Constants | `UPPER_SNAKE_CASE` | `APP_TIMEZONE` |

Exceptions: files generated by shadcn keep upstream names.

## 5. Deliberate deviations from D-024

| Deviation | Reason |
|---|---|
| `src/index.css` stays at `src/` root instead of `src/styles/` | Vite/shadcn convention; `components.json`, tests and docs point to it. `styles/` is reserved for extra CSS if ever needed. |
| `src/test/` added | Test setup and test-only helpers (contrast checker). Excluded from the app tsconfig and from Tailwind scanning. |
| Mock implementations colocated in `features/<x>/api/<x>.mock.ts`; `services/mock/` holds shared mock infrastructure | Reconciles D-024 (`services/mock`) with P1-T11 (colocated `x.mock.ts`). The lint rule enforces the boundary either way. |
| `services/registry.ts` | Single place that decides mock vs HTTP (P1-T11). |
| Route modules lazy-import dashboard pages directly (`features/dashboard/pages/*`) | Code splitting needs the page module itself; importing via `index.ts` would pull every page into the main chunk (R-022). |
| `services/registry.ts` imports feature `*.http.ts`/`*.mock.ts` and exposes `mockFixtures` | The registry is the only mock/HTTP switch; demo accounts and test links reach the UI through it, so screens never import mocks (lint rule). |
| `services/mock/hr-store.ts` imports feature schemas types and `organization/lib/hierarchy` | It emulates the backend for two features (employees, organization) and must apply the same pure rules (cycle checks) the UI previews. |
| `services/health/` instead of `features/<x>/api/` | System health is not a business domain; it is the reference implementation of the service pattern (P1-T11). Business domains still live in `features/`. |
